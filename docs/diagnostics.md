# 分层诊断设计

本文记录完整诊断的工程约束；current beta 已实现其中的基础闭环，当前验证范围及尚未覆盖的真机场景以 [开发说明](development.md) 为准。外层 TLS 与协议认证逐阶段遥测尚未实现。

## 可观测范围

免 root 可以发起本应用的 DNS、TCP、TLS、HTTP 请求，使用内核能力测试代理访问，并借助 VpnService 处理进入本应用 TUN 的流量。它不等于拥有基站日志、运营商内部路由、服务器日志或全设备任意抓包权限。

代理隧道加密后，TUN 侧看到的数据并不能单独证明隧道外层的握手细节。精确的阶段判断优先来自实际内核连接的埋点，辅助 socket 探测单独标明。

命令行只是能力入口，不会提升 Android 权限。采用应用内固定命令解析与类型化参数，不把文本传给 `sh` / `su`。普通用户使用“一键诊断”调用同一引擎。

## 探测步骤

| 步骤 | 要记录的事实 | 不能据此断言的结论 |
| --- | --- | --- |
| 网络环境 | 网络类型、网络标识变化、是否存在 VPN、系统联网状态 | 系统显示已联网就一定能访问节点 |
| 配置校验 | 内核版本、协议支持、必填字段、端口、SNI 等有效性 | 配置格式正确就说明凭据正确 |
| 节点入口 DNS | 使用的解析路径、A/AAAA 结果或解析错误；IP 字面量标记不适用 | 一次解析差异就证明 DNS 污染 |
| 入口 TCP | 对实际候选 IP:端口分别记录成功、拒绝、超时和耗时 | TCP 成功就说明代理服务可用；ICMP 不响应就说明节点故障 |
| 实际 TLS | 如果内核提供事件，记录 SNI、ALPN、证书校验结果和阶段耗时 | 通用 TLS socket 成功就等同于内核指纹、会话参数下成功 |
| 代理会话 | 内核实际发起的协议请求、明确的错误或可观察成功事件 | 所有协议都有独立的认证成功确认 |
| 经过节点访问目标 | 固定到被测节点的 HTTPS 请求、目标解析路径、响应结果、耗时 | 一个测速站失败就代表节点整体不可用 |
| 对照复测 | 同一参数、相近时间、不同网络或地址族下的观测差异 | 蜂窝失败且 Wi-Fi 成功就证明某个基站主动拦截 |

入口探测保持节点原始 SNI、端口等参数，IP 地址变化时不随意改写 SNI。current beta 起，实际节点连接保留订阅原有的 `skip-cert-verify` 设置；显式跳过时在连接页、节点页和诊断报告中提示节点身份未经证书确认。不会在失败后自动改成跳过验证。订阅 HTTPS 下载、辅助 TLS 探测及 HTTPS 测试目标仍验证各自证书，节点的设置不会关闭它们的验证。

IPv4 与 IPv6 分开记录，保留每次候选地址尝试。节点入口解析与代理访问目标时的解析是两个不同问题：目标可能在本地、内核或服务端解析，无法确定时记录未知。

HTTP 探测使用配置明确、负载很小的端点。默认只测一个，失败后最多增加一个独立目标作为对照。成功判断依据端点预期状态及可选响应特征；任意 HTTP 响应不自动算作预期访问成功。报告记录端点别名，避免与任意用户浏览流量混合。

## AnyTLS 的特殊限制

AnyTLS 在 TLS 握手后发送认证信息；协议文档说明认证失败时服务端可能关闭连接或转入 fallback。因而单凭 EOF、reset、超时或收到其他服务响应，通常不能唯一判断密码错误、协议不兼容或网络干预。

UI 不强制展示一个虚构的“认证成功”步骤。可以展示“协议会话尚未确认”，或在实际代理请求成功后说明“代理通路已验证”；后者是端到端的成功证据，不是假设存在独立认证 ACK。

仅当实际连接中有可信 TLS 完成事件，才能报告“TLS 已完成、后续阶段失败”。只有总超时日志时报告“代理连接未在时限内完成，具体阶段未知”。

## 执行与 Android 路由

诊断运行由 runId 标识，绑定节点快照、配置摘要、内核版本与起始 Network。网络切换后终止当前比较，标记环境已变化，并创建新运行；不把前后两种网络的步骤拼成一条结果。

普通直连探测必须明确绑定到底层 Network，并在需要时通过 VpnService.protect 排除 VPN，避免流量绕回自身。实际代理探测必须强制经过被测节点，不依赖当前自动选择组。对照请求不擅自修改用户当前策略和连接；优先使用隔离的诊断入口或内核定向拨号能力，具体机制在 M0 验证。

首轮源码核查发现，FlClash 的 `core/probe.go` 已使用指定代理的 `DialContext` 发起请求，并记录路由信息；可参考这条通路，不必通过全局切换策略组来诊断。`proxy-name` 必须指向实际节点；如果仍指向自动选择组或链式配置，则不宣称已固定到单一实际服务器。具体拨号能力与内核版本一起验证。

Android 嵌入优先参考移动端桥接及回调，而非让 APK 依赖外部 Controller。TUN FD 的接管、复制和关闭责任需要写成接口契约；保护失败必须返回明确状态。Go 到 Java 的回调还需明确异常如何转换为错误，避免 JNI 线程残留异常。上述实现参考来源与版本见 [upstream-review.md](upstream-review.md)。

若 always-on VPN 或 lockdown 等系统策略不允许直连探测，结果应为“受系统策略限制”，不能算作节点故障。Android 通常每个用户或工作资料同时只有一个活动 VPN；测试与其他 VPN 共存时应解释系统行为。

独立辅助探测和实际连接事件有不同的 evidenceSource，不能拼成“DNS → TCP → TLS → AnyTLS”全部属于同一 socket 的假时间线。连接复用时标记复用，不为缓存会话虚构一次新握手。

初始预算建议：入口解析 3 秒、TCP 4 秒、TLS 5 秒、代理目标请求 8 秒；整体 25 秒。每步与剩余总预算取较小值。单节点同一阶段最多一次自动重试，总尝试次数不超过两次；最多两个并行辅助探测。数值需真机校准。

取消、超时、依赖失败、权限不足分别建模，关闭 socket 与协程，恢复临时日志级别并清理诊断入口。不要将“取消”翻译为 Failed。默认用户主动启动，避免持续重试耗电及触发服务商限制。

未获并发槽位、尚未实际发送的请求使用 `not_attempted`，原因可为 `resource_busy` 或 `queue_deadline`，不归因于节点。配置或节点选择发生变化时将结果标记为 `stale` 并保留失效原因；网络变化同样使运行失效。UI 不能继续用旧观测更新当前连接结论。借鉴 FlClash 的 CoreEpoch / PicksVersion，但网络版本由本项目独立记录，不将它们当成同一种状态。

## 事件与结论

建议的内部数据结构：

```text
Observation
  runId, attemptId, connectionId?
  stage: network | config | endpoint_dns | tcp | tls | proxy_session | target_http
  state: passed | failed | unknown | skipped | cancelled | blocked | not_attempted | stale
  evidenceSource: android_probe | core_event | core_log | operator_probe
  path: direct | selected_proxy | unknown
  addressFamily: ipv4 | ipv6 | unknown
  elapsedMs, timestamp, networkSnapshotId, configEpoch, selectionEpoch
  endpointAlias, targetAlias?, errorCode?, redactedDetail?

Finding
  observedFacts[]
  possibleCauses[]
  confidence: confirmed_observation | supported_hypothesis | insufficient_evidence
  limitations[]
  suggestedActions[]
```

耗时用单调时钟测量；报告另存带时区的时间戳用于人工对照，不依靠设备墙上时钟计算耗时。connectionId 不可用时，不能把并发日志仅凭接近的时间强关联到某个请求。

“观测事实已确认”只描述事实，不暗示根因已确认。第一版采用可检查的规则，不靠语言模型凭一段日志生成确定性根因。可选自然语言解释也只能使用这些结构化事实。

典型规则：

- DNS 失败：报告解析路径与错误，后续依赖域名的入口步骤跳过；不直接说服务商服务器宕机。
- TCP refused：报告入口连接被拒绝；监听未开启、端口配置和路径上的拒绝设备均是可能原因。
- TCP timeout：报告未在预算内建立连接；不指认防火墙、运营商或基站。
- 实际 TLS 证书名不匹配：报告证书校验错误，建议核对 SNI 与服务端证书，不自动跳过验证。
- TLS 已完成、代理通路未验证：仅在实际内核证据支持时给出此阶段结论，原因保留不确定。
- 目标 A 失败而目标 B 经同一节点成功：至少一个代理请求已成功，优先检查 A 的路径或目标，不能判定节点整体故障。
- 多个地区标签同时失败：先检查是否共享入口和本地配置，不能假设标签代表独立网络。

## mihomo 适配

Android 主适配采用 Kotlin facade → Go 移动端桥接 → mihomo；已有工程分别展示了 gomobile 回调和 JNI/C 桥接路径，这两套接口不能混当成统一 ABI。REST 适配是可选通道，不要求默认开放监听端口。

可用候选接口包括版本、节点列表、节点 delay、实时 logs、connections 和 DNS query。官方在线文档中的结构化日志选项需要在固定版本上验证。API 的 `/debug/pprof` 用于运行时性能分析，不能充当网络链路诊断接口。

若明确启用 Controller，只监听 loopback 并使用随机 secret。它仍是敏感控制面，不能因为 loopback 就假定其他本地应用完全不可访问；应用内优先使用移动端桥接或受保护 IPC。secret 不进入普通日志或导出文件。

FlClash 的固定版本已经区分 delay 与 HTTP probe，但所读 `ProbeResult` 没有提供本项目所需的节点 DNS / TCP / 外层 TLS / AnyTLS 逐阶段事件。此为已读接口的能力边界，不是对全部客户端或整个内核的穷尽性结论。尤其要区分两层 TLS：通过代理访问 HTTPS 测试目标时的 TLS，与节点入口的 TLS 并非同一次握手。

所有探测经过 CoreAdapter：声明支持哪些阶段事件，记录版本和能力。缺失的事件返回未知；如果需要上游补丁，最小化修改，输出结构化错误和关联 ID，并避免修改代理协议本身。

## 服务商协作与报告

客户端不能凭空向任意节点发送自定义健康请求并期待它支持。无服务商配合时，只运行标准协议连接与有限的目标访问测试。

以后可由服务商自愿提供经过认证的诊断端点或按时间查询的日志，帮助确认入口接收、认证、出口访问等环节。只有双方事先设计且兼容时才传递关联标识，不随意给 AnyTLS 报文增加字段。服务端日志也只证明该观测点的事实。

默认导出内核版本、网络类型、时间、步骤状态、错误代码及稳定别名。不导出密码、订阅 token、完整配置、完整连接列表或用户浏览内容。对节点名称和错误字符串里的 URL、用户名、IP、域名进行字段过滤及二次脱敏，防止通过异常消息泄漏。用户在预览页选择额外字段后重新生成报告；没有自动上传动作。

## 必须覆盖的验证场景

验证需要受控服务器和真机，不用真实服务商全网扫描代替。

| 情境 | 预期 |
| --- | --- |
| NXDOMAIN、解析超时、IP 字面量 | 区分错误与不适用，正确跳过依赖阶段 |
| TCP 拒绝与无响应 | 区分 refused / timeout，不猜根因 |
| 证书错误、SNI 错误、握手停滞 | 实际内核与辅助 TLS 探测分别记录 |
| AnyTLS 错误凭据与 fallback | 无明确证据时保持原因未知 |
| 一个目标失败、另一个成功 | 不输出节点整体故障 |
| IPv6 失败、IPv4 成功 | 保留地址族差异和实际选用路径 |
| 自动选择组切换 | 被测节点仍固定，结果无串线 |
| 并发资源耗尽与配置更新 | 未发送显示未执行，旧结果显示失效，不误报节点异常 |
| VPN 循环、lockdown、权限撤销 | 明确系统或路由限制，清理资源 |
| TUN 接管失败与 protect 回调失败 | 关闭应关闭的 FD，停止无效 VPN，输出本地集成错误 |
| 蜂窝 / Wi-Fi 切换、会话复用 | 划分运行与连接，不虚构握手 |
| 取消及总预算耗尽 | 有确定终态，资源释放，不继续后台探测 |
| 节点名、嵌套错误含凭据 | 报告与普通日志不泄漏敏感字段 |

技术依据及合规资料列于项目 README；本文中的超时、UI、模块边界属于设计建议，尚待实测。

## current beta 实现边界

实际代理请求在 DialContext 返回错误处保留只在内存使用的包装类型，借此区分建立代理通道与 HTTP transport 后续处理。根据可遍历的错误类型识别 x509 信任 / 名称 / 有效性错误、QUIC 握手超时或加密错误、内核解析失败和通道超时；只向 Kotlin 返回固定代码。测试目标证书失败与代理通道证书失败分别显示。没有可识别类型时保持阶段未知，不解析任意原始错误字符串来猜测密码或网络拦截。

Hysteria2 / TUIC 使用 UDP/QUIC，入口 TCP 与标准辅助 TLS 跳过，不把跳过计为失败。现有类型分类不等于完整握手时间线或认证遥测。真实本地 Hysteria2 测试覆盖可信、不可信、错误名称及保护失败；Android 测试覆盖 QUIC Initial 经受保护 UDP socket 发出。模拟器与本地服务结果不替代真实手机和节点验证。

导入失败详情按协议、固定字段标签和受影响节点数统计；构造参数组合错误与字段 / 值格式问题分开。任意未知字段名和字段值不会进入详情或报告；原订阅地址、UUID、密码仍只用于本机加密资料。旧资料需重新导入或手动更新才能生成新增详情。

## current beta VLESS 模板兼容

订阅生成器可能为 VLESS 保留 VMess 的 alterId / cipher 占位字段。固定 Mihomo 的 VlessOption 不读取这两个字段，不能将它们当作 VLESS 的加密或认证设置。导入时移除有界标量占位值后，再执行原有字段及安全校验；VLESS 的 encryption 与 TLS 等真实设置仍原样保留。不是全局忽略未知字段，也不适用于 VMess。旧版拒绝的节点须更新订阅或重新导入才会重新处理。

## current beta 状态显示

“证书校验：按配置跳过”是导入参数，不是一次连接失败。证书策略步骤显示“跳过”，不标为失败或未知。所选节点的连通性独立读取真实代理测试结果，初始为未测试，只有 PROXY_OK 的通过观测才显示本次访问成功。证书策略不能充当成功证据；节点、目标变化或终止状态不能继续显示旧成功。不增加自动后台测试或数据上传。

current beta 按用户要求将静态证书提示改为首次弹窗，关闭后普通页面不再常驻，完整脱敏报告仍保留策略。实际拨号链使用构造时的组选择快照；辅助入口探测仍为直连，报告明确两者路径不同，不能据此确定代理链哪一跳出错。没有逐跳握手遥测，也没有失败后直连重试。
